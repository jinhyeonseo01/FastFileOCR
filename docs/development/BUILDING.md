# Building FastFileOCR

## Requirements

Windows x64, Node.js 22+, the Rust toolchain in rust-toolchain.toml, Visual Studio C++ desktop tools with Windows SDK, and Python 3.12 for build-time layout export.

```powershell
npm ci
npm run resources:prepare
npm run desktop
```

The resource preparation step downloads pinned CPU/Vulkan/CUDA llama.cpp engines, CUDA runtime, PDFium, ONNX Runtime, MSVC libraries and licenses. Python and PyTorch are used only to export and compare the layout graph; end users do not install them.

## Installer

```powershell
npm run installer
```

Output: src-tauri/target/release/bundle/nsis/FastFileOCR_0.1.1_x64-setup.exe, plus a SHA-256 file and build-info.json. Tauri's NSIS bundler generates the installer. The installer includes WebView2 for computers that do not already have it. The default build is unsigned.

## Validation and formatting

```powershell
npm run check
npm run locales:check
npm test
npm run resources:check
npm run format
cargo fmt --manifest-path src-tauri/Cargo.toml
```

After building the installer, run npm run installer:test to verify the Rust data helper and actual NSIS installation, settings backups, language selection, retention, independent cleanup choices and unowned-directory rejection in isolated fixtures. The release workflow runs this gate too.

To check the real release endpoint without opening the app, run cargo run --manifest-path src-tauri/Cargo.toml --example smoke -- --check-updates. An optional owner/repository argument checks a fork.

Rust PDF import tests require the prepared PDFium library. Public sample documents are generated by node scripts/dev/make-fixtures.mjs.

## Releases and update discovery

Push a vMAJOR.MINOR.PATCH tag to the GitHub repository on a commit that contains .github/workflows/release.yml. The workflow sets the application version from the tag, builds and verifies the installer, and attaches it to GitHub Releases.

```powershell
git push -u origin main
git tag -a v0.1.1 -m "FastFileOCR v0.1.1"
git push origin v0.1.1
```

The app defaults to jinhyeonseo01/FastFileOCR for update checks, including local builds and older settings with an empty repository. The workflow supplies FASTFILEOCR_GITHUB_REPOSITORY from github.repository; forks can override it at build time or in Settings. A repository without a public release shows a separate status instead of an HTTP error.

The updater uses the latest stable release, accepts the exact Windows installer name for that version, requires a matching .sha256 asset, verifies the download and rechecks the hash before launching the interactive installer. A checksum establishes integrity relative to the selected release source; it is not a code-signing certificate.

## Data lifecycle

The installer saves DataDir and initial Language under HKCU/Software/FastFileOCR. The selected root has a .fastfileocr-data ownership marker. Settings, models, logs, updates and new workspaces live under it. Existing workspaces may remain in their original folders.

The default root is %LOCALAPPDATA%/FastFileOCR. A test launch can override it with FASTFILEOCR_DATA_DIR. Settings use a versioned schema, preserve the workspace reference, and reject schemas from a newer app.

Selecting a populated general folder creates a dedicated FastFileOCR child (or Data inside an application folder); the resolved location is shown before installation. Unrelated parent-folder files are preserved. Keeping settings preserves the selected data folder. A fresh start backs up settings.json and uses defaults, while retaining models and documents. Selecting a different empty data directory starts a separate data location; it does not delete or move the previous directory.

Uninstall defaults to retaining data. Removal of settings/models and removal of app-managed workspaces require separate choices. Cleanup is limited to named children of a marked folder and rejects reparse points. Workspaces outside the selected data root are never removed.

## NSIS maintenance

The Tauri CLI is pinned in package.json. scripts/build/prepare-nsis.mjs verifies and extends the matching upstream NSIS template using installer/nsis/upstream.json. Updating the CLI requires reviewing the template version, checksum and extension anchors together; preparation fails if they no longer match.

Tauri owns WebView2 installation, application files, shortcuts and version handling. installer/nsis/hooks.nsh adds data-location and settings pages, language handoff and opt-in cleanup. installer/helper is a dependency-free Rust crate that validates paths, backs up settings and removes only known children of an owned folder. Its runtime is statically linked so it also works before application runtimes are installed.

The installed data-location.ini records the data root for uninstall. Reinstall-triggered uninstall and /UPDATE always preserve data. Ordinary silent uninstall also preserves data unless explicitly passed /REMOVEUSERDATA=1 or /REMOVEDOCUMENTS=1. Installer options include /LANGUAGE=1033 (English), 1042 (Korean) or 1041 (Japanese), /DATADIR=, and /FRESH=1. NSIS /D= selects the application directory and must be the final argument, without quotes around its value.

The app's existing GitHub release downloader launches the NSIS installer interactively after checksum verification. It does not currently use tauri-plugin-updater. Moving to that plugin later also requires an update-signing key and release metadata; changing installer type alone does not configure them.
